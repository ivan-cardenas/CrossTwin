# Raster pipeline and map frontend

## Raster Pipeline (`core/rasterOperations.py`)

1. PostGIS raster → `ST_AsGDALRaster` → temp GeoTIFF
2. Reproject to `COG_CRS` (EPSG:3857, the map's tile grid, so TiTiler reads tiles without warping; COGs written before 2026-11-12 are EPSG:4326 and still work, readers use the file's CRS) via rasterio
3. Convert to Cloud-Optimized GeoTIFF (COG) via `rio-cogeo`
4. COG stored on disk under `cogs/<app_label>/`, named `<index or ClassName>_<source>_<date>_<id>.tif` (`_cog_filename`; the class name keeps models of one app with the same source, date and id apart)
5. TiTiler serves tiles from the COG path. `core/views.py` adds `v=<COG mtime>` to tile URLs and `tiler.py` then sends `Cache-Control: immutable`, so browsers keep tiles until the COG is rewritten; `/info` is cached per file version (`_titiler_info`, WGS84 bbox from `info.geojson`). Keep `TITILER_BASE_URL` on `127.0.0.1`: TiTiler listens on IPv4 only and Windows resolves `localhost` to `::1` first (~2 s per request)

## Map Frontend (`mainMap/`)

- `map_view` renders `mainMap.html` with Mapbox token
- `available_layers` returns the full layer catalog (vector + WMS + raster) as JSON
- `model_geojson` builds one raw SQL statement per request (`_geojson_sql`): `ST_AsGeoJSON(ST_Transform(..., 4326), 6)`, FK display names via `LEFT JOIN` (not per-row sub-SELECTs; extra columns of the FK target for the popup are listed in `POPUP_RELATED_FIELDS` and arrive as `<fk>__<field>`, e.g. the soil type's name/group/infiltration rates on `SoilArea`), optional `?bbox=minLng,minLat,maxLng,maxLat` (`&&` on the GiST index) and `?zoom=z` (`ST_SimplifyPreserveTopology` to ~1 px below zoom 14; points never simplified). It returns PostgreSQL's JSON text as-is (`HttpResponse`, not `JsonResponse`) with an `X-Cache: HIT|MISS` header.
- GeoJSON responses are cached in the `geojson` cache alias (`CACHES` in settings: local memory, 64 entries, bodies ≤ 8 MB, 2 min) under a per-model version from `core/cache.py` (`layer_version` / `bump_layer_version`). The version only changes on writes made through Django, so edits from QGIS/psql/other scripts show up only when the entry expires — hence the short TTL (`GEOJSON_CACHE_TTL`). Local memory is per process: with several workers, point `CACHES` at Redis so invalidation reaches all of them.
- Map styles live in the `mainMap/styles/` package: `layerStyles.py` (`LAYER_STYLES` per registry key: catalog `color`, Mapbox `layers`, optional `legend`; `FALLBACK_COLORS`; building type colours), `soilStyles.py` and `landCoverStyles.py` (style + legend built per request in `available_layers` from the classes present in the DB), `rasterStyles.py` (raster colormaps/value ranges, used by `core/views.py`). Add a new layer's style to `LAYER_STYLES`; a data-driven one gets its own module there.
- `layer_bounds` returns WGS84 `[[west, south], [east, north]]`, using `ST_EstimatedExtent` only for tables with ≥ `ESTIMATED_EXTENT_MIN_ROWS` (100 000) rows. The estimate is as old as the last `ANALYZE`, so smaller tables get an exact `ST_Extent`.
- `Layers.js`: vector layers with ≥ `VIEWPORT_LOAD_MIN_FEATURES` (5 000, in `Config.js`) features load by viewport and reload on `moveend` (debounced, superseded requests aborted); `zoomToLayer` uses `/bounds/` for them. Administrative layers always load whole — their click handlers and the admin-unit panels need every unit.
- Floating map overlays (toolbar, layers panel, side panel, population dock, legends, WMS scrubber, tour card) share `--overlay-bg`/`--overlay-blur`/`--overlay-shadow` tokens in `mainMap.css` and are draggable by their header via `core/static/js/Draggable.js::makeDraggable(el, handleSelector)` (delegated, so handles added later work; double-click the handle to reset; disabled below 768 px). Wiring is in `Events.js::initializeUI`.
- WMS tiles (`addWmsLayer`, `wmsTileUrlForTime`, the groundwater source) use `WMS_TILE_SIZE` (512, `Config.js`) for both `tileSize` and the `width`/`height` params — keep the two equal. Remote WMS cost is per request (~0.5–3 s each at KNMI), so bigger tiles = fewer requests. Time-dimension WMS sources (the radar) stop at `WMS_TIME_MAX_ZOOM` (8; the radar grid is ~1 km, Mapbox overzooms with nearest resampling), and `Layers.js::prefetchWmsFrames` warms the visible tiles of the other frames one request at a time (nearest frames first, restarted on `moveend`/frame refresh; URLs built like Mapbox's `getTileBBox` + `roundBboxInUrl` so they hit the browser cache). `weather/views.py::wms_tile_proxy` caches tiles in `CACHES["wms_tiles"]` (24 h for `TIME=` frames, 5 min otherwise), sends matching `Cache-Control`, and reports `upstream;dur` / `cache;desc` in `Server-Timing`. Upstream calls go through the module-level `_session` (keep-alive); mock `weather.views._session.get` or `_fetch_with_retry` in tests, and clear `get_cache("wms_tiles")` in `setUp`.

- **Stored buildings over the basemap's** (`Map_init.js::addBuildingMask`): wherever the DB holds buildings, a Mapbox `clip` layer (`db-building-mask`, from zoom `DB_BUILDINGS_MIN_ZOOM` 14) erases the basemap's extrusions and 3D models, and `db-base-buildings` draws the stored `builtup.Building` rows instead (viewport-loaded from the GeoJSON endpoint, same colours as the basemap, height expression from the catalog style), so editor/generator buildings and deletions show in every view; where nothing is imported the basemap's buildings stay. The clip is kept as the topmost layer (`keepBuildingMaskOnTop` on `styledata`): Mapbox compares the clip's draw-order index with a building layer's `style.order` index, and layers added later shift `3d-buildings` in the latter, so a clip placed just above it stops clipping when a tool loads its layers. It does not erase line layers, so the basemap's building edges are off while the mask is in view. `db-base-buildings` follows `sync3DBuildings()`'s hide rule.

- **Scenarios panel** (time menu's *Compare scenarios* → `Panels.js::showScenarios` → `/weather/climate/panel/?climate=`, `weather/views.py::climate_panel`, partial `weather/partials/climate_panel.html`): the KNMI'23 climate scenarios (`weather/calculations/climate.py`: Table 1 of KNMI Publication 23-03, national averages vs 1991-2020, per season; the Klimaateffectatlas presets current / 2050 high / 2100 high, "high" = Hd, plus all of Ld/Ln/Hd/Hn × 2030…2100 every 10 years: 2050/2100 published, the other decades `climate.interpolate`d linearly in time from 0 at 2005, flagged `interpolated`, drawn as a clickable curve per pathway by `weather/views.py::_scenario_curve`; every applied change is the scenario's minus the change already in the observed year (`observed_year` argument, `climate.observed_offset`: one value for all pathways, the mean of the four; nothing for a scenario year at or before it; not the design rain or the vs-1991-2020 table); heat mode `climate_heat` = `average` (Table 1 daily max/min, understates heat waves) or `warmest` = heat-wave day: the warmest-day change at the nearest of KNMI's five key-figure stations, `climate.STATION_EXTREMES`, from klimaatscenarios-data.knmi.nl, nearest to the unit's point on surface, day and night, with the summer humidity/wind/radiation changes; the panel lists the stations' heat key figures). A choice in the panel goes through `setTime` (shown on the time chip), and `mainMap.js::climateParam()` adds `climate=&climate_heat=` to the heat and water panel URLs. Heat: `urban_heat/views.py::_climate_weather` moves the live/station weather by the season's change (`apply_to_weather`: Tx by day, Tn by night, RH, wind, radiation scaled by the seasonal mean), the sliders start (and Reset returns) there, the Plan banner names the scenario. Water: the Rain Event default × the summer 1-day 10-year rain change (`design_rain_mm`), recharge with seasonal daily rain (`apply_to_daily_rain`, needs `daily_months` from `yearly_water_balance`) and yearly Makkink ET changes. A what-if: nothing stored, SOLWEIG/LST keep observed weather. Choosing a scenario also sets the population year (`climate.population_year`: current → 2025 = `CURRENT_POPULATION_YEAR`, else the scenario year; the panel's `data-climate-year` → `setTime({year, pathway, heat}, {refreshPanel: false})`; the year slider has every decade to 2100), and a year picked on the time chip gives the scenario of that year (a decade 2030–2100 → that year with the chosen pathway, High-dry by default; other years → current). `Panels.js` loads in `<head>`, so its top-level listeners go on `document`, not `document.body` (null there). Years beyond the imported CBS years are `population.extrapolate`'s trend, flagged by `population.is_extrapolated` and labelled *trend extrapolation* in the water/housing/built-up panels and the population dock. The heat mode is the season of the changes: `average` = the observation's season, `winter`…`autumn`, or `warmest` = heat-wave day (`climate.season_for`, `temperature_change`). The panel's *Quick what-if* loads `mainMap/views.py::climate_effects` (`/api/climate/effects/`, nothing stored). Its **Calculate effects** CTA (staff) stores a run (`mainMap/views_climate.py`, `/api/climate/runs/`): `weather.ClimateScenarioRun` (the Climate_Change node: scenario, heat mode, station, population variant/growth/year, analysed hour + observed met, map view) whose receivers store `watersupply.ScenarioFreshWater` / `ScenarioWaterSecurity`, `housing.ScenarioHousingNeed` and `urban_heat.ScenarioHeat` (one SOLWEIG run on the shifted hour tagged `climate_run`; the current column reuses an observed run of the same hour covering the view, `solweig/scenario.py::find_baseline`, + WBGT from Tmrt, `chain.wbgt_outdoor_c`). Scenario heat rasters keep the observed hour as `date_time`; their `__str__` (`urban_heat/models.py::_measurement_label`) names the scenario and run. Observed rows are never changed: scenario rasters skip `replace_covered` and the dashboards' `_raster_stats_sql`. LST is not projected (surface reflectance); SUHII stays observed. Results are a snapshot: *Update results* re-saves the run (no GPU, seconds), *Rerun heat simulation* requeues SOLWEIG (minutes); the panel's notes sit behind "?" buttons (`core/indicator_help.py`, `climate.*`) and change cells are coloured worse/better (`mainMap.views.change_tone`) or by heat/wet/dry (`climate.change_tone`); `urban_heat.HeatInputChange` (land cover, soil, DSM, buildings; also the bulk finalizers) flags runs whose heat model is older. `docs/DAG_REVISIONS.md` argues both departures from the contract.
- **Console feed under the loader** (`core/console.py`, `core/static/js/ConsoleFeed.js`, `GET /api/console/?after=<seq>`, DEBUG or staff only): `CoreConfig.ready()` tees `sys.stdout` and `LOGGING` sends the project loggers (INFO, listed in `settings._APP_LOGGERS`) and other libraries' WARNINGs to `console.FeedHandler`, into a 500-line in-memory buffer (per process; TiTiler not captured). While any `fetch()`/HTMX request of the map page is pending, `ConsoleFeed.js` polls the feed and shows the newest 6 lines under `#map-loader` (inside `#map-loader-wrap`), fading 4 s after the work ends. Report progress of long work with `print()` or a project logger and it appears there; the polling is kept out of the runserver access log (`SkipFeedRequests`) and the query-stats log.
- `core/static/js/mainMap.js` holds `mainMap.html`'s page-level wiring (map init, the time chip, guided tour, the admin-unit-driven panel registry); the modes are `Modes.js`. It depends on `Config.js`/`map_init.js` and on `window.MAPBOX_ACCESS_TOKEN` being set inline by `mainMap.html` before it loads. As with the indicator dashboards, keep new map-page behavior in this file rather than adding inline `<script>` blocks to `mainMap.html`.

## Design tokens & motion

Editorial dark system (reference: empireai-platform.framer.website), dark by default with a light variant.

- **Tokens** live only in `core/static/css/theme.css` (`:root` and `:root[data-theme="light"]`): `--bg-*`, `--text-*`, `--border*`, `--accent*` (cool teal, kept away from red/amber data scales), `--font-display/base/mono` (Saira Extra Condensed / Geist / Geist Mono, loaded by `Templates/partials/_fonts.html`), `--r-*`, `--ease-*`, `--dur*`. Never hardcode colours in component CSS; data colour ramps and legends are the exception.
- **Components**: `.ct-btn`, `.ct-card`, `.ct-label`, `.ct-display`, `.ct-chip`, `.ct-divider`, `.ct-num`; header `.app-nav`, `.brand-mark`, `.header-btn`.
- **Theme toggle**: `js/ui/theme-init.js` (head, sets `data-theme` from `localStorage['ct-theme']`) and `js/ui/theme.js` (`[data-theme-toggle]`, fires `ct:themechange`). The landing page is pinned to dark (its 3D scene is drawn for it). The basemap style does not follow the theme yet.
- **Scroll reveals**: add `.reveal`, `.reveal-mast` or `.reveal-line` (`--i` for stagger); `theme.js` sets `[data-revealed]` via IntersectionObserver and re-scans after `htmx:afterSwap` (`window.ctReveal(scope)`). All motion is off under `prefers-reduced-motion`. Dashboard cards use a CSS-only stagger in `indicators.css` so HTMX swaps re-animate.
